🧮 1. Công Thức Tính Nhanh OSG202 (Chắc Chắn Ra FE)
Chuyên đề Công thức & Mẹo tính 5 giây
CPU Utilization
(Đa chương)		 • CPU Utilization = 1 - pⁿ
(p = tỷ lệ thời gian chờ I/O; n = số tiến trình trong bộ nhớ).
VD: p = 0.8, n = 3 ⇒ 1 - 0.8³ = 1 - 0.512 = 48.8%.
CPU Scheduling • Turnaround Time (TAT) = Finish Time - Arrival Time.
• Waiting Time (WT) = TAT - Burst Time.
• Response Time = First Run Time - Arrival Time.
• SJF / SRTF cho Average Waiting Time nhỏ nhất!
Paging & Địa chỉ ảo • 1 KB = 2¹⁰, 1 MB = 2²⁰, 1 GB = 2³⁰, 1 TB = 2⁴⁰.
• Page Number = ⌊Virtual Addr / Page Size⌋.
• Offset = Virtual Addr mod Page Size.
• Số trang (Pages) = Virtual Space / Page Size.
• Kích thước Page Table = Số trang × Kích thước 1 entry.
TLB & Effective Access Time (EAT) • Có TLB (hit ratio α, TLB time t, RAM time m):
  EAT = α(t + m) + (1 - α)(t + 2m).
• Có Page Fault (tỷ lệ lỗi p, RAM m, Disk/Swap S):
  EAT = (1 - p)·m + p·S.
Banker's Algorithm
(Deadlock)		 • Need = Max - Allocation.
• Tiến trình chạy được khi Need ≤ Available.
• Chạy xong thì thu hồi: Available = Available + Allocation.
• Tìm được chuỗi chạy hết tất cả tiến trình ⇒ Safe State.
Inode Max File Size Giả sử Block Size = B, Pointer Size = P ⇒ 1 block chứa K = B/P con trỏ:
• Direct (d): d · B
• Single Indirect: K · B
• Double Indirect: K² · B
• Triple Indirect: K³ · B.
Disk Scheduling • FCFS: Phục vụ đúng thứ tự đến.
• SSTF: Chọn track gần đầu đọc nhất (dễ gây starvation).
• SCAN (Elevator): Quét 1 chiều tới tận biên rồi quay đầu.
• C-SCAN: Quét 1 chiều tới biên rồi nhảy về đầu kia (chỉ đọc 1 chiều).
Bảng RAID (0–6) • RAID 0: Striping (nhanh nhất, 0 dự phòng, chết 1 ổ mất hết).
• RAID 1: Mirroring (nhân đôi ổ, chịu chết 1 ổ/cặp, tốn 50% dung lượng).
• RAID 2: Bit-level + Hamming code.
• RAID 3: Byte-level + 1 ổ Parity riêng (tệ nhất khi đọc từng sector lẻ!).
• RAID 4: Block-level + 1 ổ Parity riêng (nghẽn cổ chai ổ parity).
• RAID 5: Block-level + Distributed Parity (chịu chết 1 ổ, cần ≥ 3 ổ).
• RAID 6: Dual Distributed Parity (chịu chết 2 ổ cùng lúc, cần ≥ 4 ổ).
📖 Lý Thuyết Ngắn Gọn 10 Chương OSG202 (Tanenbaum)

1. Tổng Quan HĐH, Chế Độ CPU & System Calls

  • Dual-mode: Kernel Mode (đặc quyền, chạy mọi lệnh I/O & phần cứng) vs User Mode (bị giới hạn). Chuyển từ User → Kernel bằng lệnh TRAP (System Call).
  • Kiến trúc HĐH: Monolithic (nhanh, toàn bộ trong kernel — Linux/Unix) vs Microkernel (an toàn, tin cậy, chạy driver ở user space — Minix 3, QNX).

2. Tiến Trình (Process) & Luồng (Thread)

  • 3 trạng thái chính: Running → Blocked (chờ I/O) → Ready (I/O xong) → Running (được chọn). BẪY Không thể đi trực tiếp từ Blocked → Running!
  • Thread chia sẻ: Address space (Code, Data, Heap), Open files. Thread giữ RIÊNG: Program Counter (PC), Registers, Stack, State.
  • User-level thread: Chuyển ngữ cảnh siêu nhanh, nhưng 1 thread gọi blocking syscall sẽ block cả process.

3. Đồng Bộ Hóa & IPC (Synchronization)

  • Race Condition: Nhiều tiến trình cùng đọc/ghi dữ liệu chia sẻ, kết quả phụ thuộc thứ tự chạy.
  • 4 điều kiện Critical Region: Mutual Exclusion, Không giả định tốc độ CPU, Tiến trình ngoài CS không được chặn tiến trình khác, Không chờ vô hạn (No starvation).
  • Semaphore: down/P/wait (giảm, nếu = 0 thì ngủ) và up/V/signal (tăng, đánh thức). Mutex: chỉ có 2 trạng thái Locked/Unlocked. Monitor: cấu trúc ngôn ngữ cấp cao có condition variable.

4. Lập Lịch CPU (CPU Scheduling)

  • Batch (Non-preemptive): FCFS (dính Convoy Effect), SJF (tối ưu WT).
  • Interactive (Preemptive): Round Robin (quantum quá nhỏ → tốn context switch; quantum quá lớn → biến thành FCFS), Priority, Multi-level Queue.
  • Real-time: Hard RT (trễ deadline = thảm họa) vs Soft RT. Rate Monotonic (ưu tiên chu kỳ ngắn) & EDF (ưu tiên deadline sớm nhất).

5. Deadlock (4 Điều Kiện Coffman)

  • Deadlock chỉ xảy ra khi có ĐỦ CẢ 4 điều kiện: (1) Mutual Exclusion, (2) Hold and Wait, (3) No Preemption, (4) Circular Wait.
  • 4 chiến lược xử lý: Ostrich (lờ đi — Unix/Windows), Detection & Recovery, Avoidance (Banker's Algorithm), Prevention (phá 1 trong 4 điều kiện).

6. Quản Lý Bộ Nhớ, Phân Trang & Phân Đoạn

  • Phân mảnh (Fragmentation): Paging chỉ bị Internal (phân mảnh nội ở trang cuối), KHÔNG bị External. Segmentation chỉ bị External (phân mảnh ngoại).
  • Cấp phát động: First Fit (nhanh nhất, tốt nhất thực tế), Best Fit (tạo nhiều lỗ nhỏ vụn), Worst Fit, Next Fit.
  • TLB (Translation Lookaside Buffer): Cache phần cứng lưu ánh xạ Page → Frame ngay trong MMU.

7. Thay Thế Trang (Page Replacement)

  • Optimal: Thay trang lâu dùng lại nhất trong tương lai (lý tưởng, không cài đặt được).
  • FIFO: Đơn giản nhất nhưng dính Belady's Anomaly (tăng số frame lại tăng page fault!).
  • LRU: Tốt gần bằng Optimal, không dính Belady. Clock / Second Chance: dùng R-bit xấp xỉ LRU giá rẻ.
  • Thrashing: Hệ thống dành gần hết thời gian để swap trang (page fault liên tục) do thiếu RAM / tập Working Set quá lớn.

8. Hệ Thống Tập Tin (File Systems)

  • Contiguous: Đọc tuần tự cực nhanh, dễ bị phân mảnh ngoại & khó mở rộng file.
  • Linked List / FAT: Không phân mảnh ngoại; FAT đưa bảng liên kết lên RAM nên truy cập ngẫu nhiên nhanh hơn nhưng tốn RAM khi đĩa lớn.
  • i-node (Unix/Linux): Lưu metadata + con trỏ trực tiếp & gián tiếp; chỉ nạp i-node của file đang mở lên RAM.
  • Hard Link: Trỏ cùng 1 i-node (không qua partition khác). Symbolic/Soft Link: Lưu đường dẫn path (qua partition khác được, nhưng xóa file gốc sẽ gãy link).

9. Hệ Thống I/O & DMA

  • Programmed I/O (Polling): CPU chờ bận (busy-wait) kiểm tra liên tục.
  • Interrupt-driven I/O: CPU làm việc khác, thiết bị xong thì ngắt (mỗi byte/word 1 ngắt).
  • DMA (Direct Memory Access): Bộ điều khiển DMA truyền thẳng cả block giữa thiết bị và RAM, chỉ ngắt CPU 1 lần duy nhất khi truyền xong!

10. Bảo Mật & An Toàn (Security)

  • ACL (Access Control List): Gắn theo tài nguyên/đối tượng (cột của ma trận bảo vệ).
  • Capability List: Gắn theo tiến trình/người dùng (hàng của ma trận bảo vệ).
  • Buffer Overflow: Ghi tràn mảng trên Stack để ghi đè Return Address, nhảy sang thực thi mã độc.
